### Phase 1: Morphological Analysis — 系统参数矩阵

#### 维度 1：信息源（7类）

| 类型 | 具体来源 | 信号特征 |
|------|---------|---------|
| A. 公司官网动态 | 标的公司官网（产品发布、招聘、IR页面） | 基本面领先信号 |
| B. 平台生态数据 | B站活跃度/内容趋势等互联网标的 | 经营状态实时感知 |
| C. 财经RSS | 财联社、东方财富等 | 结构化新闻流 |
| D. 交易所公告 | 港交所/沪深交易所 | 第一手合规信息 |

| G. 政策监管 | 证监会、国务院、行业政策 | 板块级别影响 |

#### 维度 2：Agent架构（三条管道并行）

| Agent | 职责 | 触发方式 | 速度要求 |
|-------|------|---------|---------|
| 采集Agent | 爬取/拉取，去重归一化 | 30min定时 | 中 |
| 交叉验证Agent | 关键词事件归并，信源加权，矛盾检测 | 采集完成后 | 中 |
| 研读Agent | 深度分析，分类，关键词，利好/利空标签 | 验证完成后 | 可稍慢 |
| 事件引擎 | 事件创建/更新、热度计算、生命周期推进 | 研读完成后 | 中 |
| 建议Agent | 基于标的全部活跃事件热度面板+信息源覆盖状态综合研判 | 事件更新后 | 可稍慢 |
| 推送Agent | ntfy.sh分级推送 | 建议完成后 | 快 |
| RSS哨兵Agent | 实时监听RSS，快速LLM筛选 | 实时 | 快 |
| 随机巡游Agent | 随机访问信息源池，抓热点 | 随机间隔 | 快 |

**Agent管道：**
```
采集Agent → 交叉验证Agent → 研读Agent → 事件引擎 → 建议Agent → 推送Agent
   (采)         (验)           (读)        (态势)       (判)        (送)
```

**关键设计决策：**
- 交叉验证 = 关键词事件归并 + 信源权重 + 矛盾检测
- 研读Agent只负责"读懂"，不给建议
- 建议Agent必须接收该标的全部活跃事件热度面板 + 信息源覆盖状态才能研判
- 纯LLM研判，不加规则引擎
- 事件去重以URL为唯一ID

#### 维度 3：分析方法

- 采集Agent输出的每条信息附带提取的简单关键词
- 交叉验证Agent用关键词做事件归并（同一事件识别），信源加权评估置信度，矛盾检测标记待确认
- 研读Agent对验证后信息做摘要、关键词提取、利好/利空分类、与持仓关联度评估
- 建议Agent基于全局事件态势（多事件叠加态）给出研判

#### 维度 4：推送机制

- **渠道：** ntfy.sh 单渠道，通过priority字段分级
  - urgent(5) — 号外事件
  - high(4) — 重要变动
  - default(3) — 常规简报
  - low(2) — 无异常轻推/信息存档
- **频率：** 每30min必推，有料高优先级，无料低优先级确认系统存活
- **号外回流：** 号外推送后自动归入下一周期简报
- **简报格式：** 固定头部元数据区标注配置信息源/本次采集源/失败源/数据时间窗口

#### 维度 5：存储与状态

- 事件去重库（URL为ID）
- 简报归档（支持回溯查询）
- 持仓/关注列表配置（标的 → 信息源映射）

**事件生命周期状态机：**
```
发现 → 验证 → 扩散监控 → 高潮标记 → 消退确认 → 归档
```

**热度分数：** 信息源提及数 x 信源权重 x 时间衰减因子

**建议Agent输出规范：**
- ACH框架：多假设（涨/跌/横盘）逐一用活跃事件验证/反驳
- 概率化表达 + 每个事件的影响权重归因
- 每条判断强制附带原文引用 + 原始URL溯源

### Phase 3: Chaos Engineering — 压力测试

| 风险 | 严重度 | 应对机制 |
|------|--------|---------|
