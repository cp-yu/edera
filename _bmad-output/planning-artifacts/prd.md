# Product Requirements Document - stockImformation

**Author:** Yunxin
**Date:** 2026-04-09

## Executive Summary

stockImformation 是一个面向港股/A股个人交易者的信息分析与决策辅助系统。系统围绕用户关注标的持续收集多类公开信息源，输出结构化摘要、事件级关联分析、交易建议与可追溯证据，并通过通知与 Web 界面交付结果。

核心目标：将交易者从分散的信息采集和人工分析中解放出来，使其在更短时间内获得可行动、可追溯、可复盘的判断依据。系统既要稳定输出常规简报，也要在重要事件发生时快速给出提醒与判断支持。

信息采集应支持结构化公开源与非标准公开源两类接入方式，以适配不同类型的信息源特征。

目标用户：个人交易者（初期自用，后续可能开源）。

免责声明：系统产出仅供参考，不构成投资建议。

### What Makes This Special

- **信息源可定制：** 用户可按标的配置和调整信息源，不被单一平台的信息流约束
- **跨源关联分析：** 系统可将来自不同来源的相关信息归并为统一事件，帮助用户识别信息之间的关联性
- **两层价值输出：** 系统既支持快速行动判断，也支持事后查看完整依据与关联链路
- **可追溯建议输出：** 每条建议均应附带来源证据、原因归因与原始信息溯源，便于用户验证与复盘

## Project Classification

- **项目类型：** Web App（多渠道信息消费与配置管理）
- **领域：** Fintech（港股/A股交易信息分析与辅助）
- **复杂度：** 高（金融领域、多信息源采集、分析链路、实时性要求）
- **项目状态：** Greenfield（全新项目）

## Success Criteria

### User Success

- **时间解放：** 用户从全时段盯盘转为仅关注通知推送，信息处理时间减少 95%
- **即时感知：** 重要公告/事件推送延迟目标 ≤1min，最迟不超过 5min；urgent 事件不受常规简报周期影响
- **决策可行动：** 每条建议直接关联买/卖/持有动作，附带原因归因和原文溯源，用户无需二次查证

### Business Success

- **核心指标：** 系统支持的模拟组合按周统计时，相对同期基准指数实现每周超额收益 ≥3%
- **3个月目标：** 系统稳定运行，覆盖主要持仓标的，日常简报和号外推送形成可靠节奏
- **开源指标（远期）：** GitHub Star、Fork、Issue 活跃度反映社区认可

### Technical Success

- **采集可靠性：** 每周期简报元数据明确标注成功/失败源，采集成功率 >85%
- **推送可达性：** 重要通知到达率 >99%
- **系统存活性：** 系统应以固定频率持续输出通知或简报，使用户可感知系统处于在线状态
- **LLM幻觉防护：** 每条判断强制原文引用 + URL溯源链，可验证率 100%

### Measurable Outcomes

- **信息覆盖性：** 系统按独立时间条目数统计时，对同花顺同类信息流的周覆盖条目数应大于或等于同期对照条目数
- **建议方向参考价值：** 事后回溯建议方向与价格变动一致率，作为持续追踪优化指标（不预设硬目标）
- **推送延迟：** 号外事件 ≤1min（目标），≤5min（底线）；交易时段常规简报每15min一次，非交易时段至少提供开盘前、竞价阶段、收盘后三次固定简报；urgent 事件不受常规简报周期限制
- **Dashboard 复盘使用率：** 用户每周至少使用 Dashboard 进行历史复盘 2 次
- **Dashboard 决策辅助时长：** 用户从打开 Dashboard 到完成一次初步判断的时间应 ≤5min

## User Journeys

### Journey 1: 日常简报 — "一切正常，无需行动"

**角色：** Yunxin，个人交易者，持有港股/A股若干标的

**Opening Scene：** 工作日下午，手机收到一条常规通知。Yunxin 瞄一眼摘要 — 各标的无异常波动，信息与持仓预期一致。

**Resolution：** 手指划掉通知，继续手头的事。全程 <5秒。系统确认了"没有意外"，这本身就是价值。

### Journey 2: 日常简报 — "情况有变，需要评估"

**Opening Scene：** 同样场景，但摘要中某个标的出现利空信号，与持仓预期不符。

**Rising Action：** Yunxin 打开股票交易网站查看实时行情，同时打开 Web 界面查看该条信息的详细分析 — 信息来源、利空分类依据、关联事件。

**Climax：** 综合股价走势和系统分析，决定是否调整仓位。

**Resolution：** 做出决策（持有/减仓/清仓），整个评估过程 5-10 分钟。

### Journey 3: 号外事件 — "立即行动"

**Opening Scene：** 手机收到高优先级通知，某标的出现重大政策变动。

**Rising Action：** 看到摘要，判断需要立即操作。直接打开交易软件完成买入/卖出。

**Climax：** 操作完成后，打开 Web 界面查看完整简报和分析链，验证决策依据。

**Resolution：** 确认系统判断合理，或发现补充信息需要后续关注。

### Journey 4: 信息源适配 — "接入新信息源"

**Opening Scene：** Yunxin 想接入一个新的信息源（如某公司官网IR页面），或买入新股票需要关联信息源。

**Rising Action：**
- **标准公开源：** 用户直接添加可直接接入的信息源，绑定标的后生效
- **非标准公开源：** 用户为该信息源补充接入配置或规则，使系统能够识别与采集该源内容

**Climax：** 系统完成首次抓取验证。

**Resolution：** 信息源正式上线，下一个采集周期纳入。也包括反向操作：剔除低质量信息源、删除不再关注的标的。

### Journey 5: 复盘与分析调优 — "系统越用越准"

**Opening Scene：** 周末，Yunxin 回顾本周交易，想验证系统建议的准确性。

**Rising Action：** 打开 Web 界面历史页面，对比历史建议方向与实际股价变动。

**Climax：** 发现某类信息源权重偏高/偏低，或某类分析逻辑有优化空间。

**Resolution：** 调整分析参数或配置，提升后续分析质量。

### Journey 6: 采集故障 — "信息源执行异常"

**Opening Scene：** 某个信息源因页面改版、访问限制或内容结构变化导致采集异常。

**Rising Action：**
- **小问题 → 自动恢复：** 系统自动尝试恢复，并记录结果
- **大问题 → 上报：** 系统无法自行恢复时，通知用户处理，并保留后续人工或外部辅助修复入口

**Resolution：** 信息源恢复正常；或该信息源临时标记为不可用，简报元数据体现降级状态。

## Domain-Specific Requirements

### 合规与监管

- **定位：** 学习/研究用途的个人工具，不涉及资金托管、交易执行或用户数据收集
- **免责声明：** 系统产出不构成投资建议，仅供学习参考
- **不适用项：** KYC/AML、PCI DSS、金融牌照等传统 fintech 合规要求均不适用
- **审计留存：** 建议记录默认长期保留，并提供按时间条件删除的接口
- **审计字段：** 每条建议至少保留标的、时间、建议方向、核心原因、置信度、原文来源 URL、原文引用片段
- **状态历史：** 系统应记录事件或建议的状态变更历史，包括初次发现、更新、降级、归档等关键状态

### 审计要求

- **建议审计完整性：** 所有建议记录必须具备最小审计字段，缺失任一字段时不得进入正式留存
- **删除能力：** 系统应支持按时间条件触发的建议记录删除能力
- **状态追踪：** 系统应对事件与建议的关键状态变更保留可查询历史
- **证据可回溯性：** 审计记录必须能够回溯到对应来源 URL 与引用片段
- **投资上下文留存：** 每条建议记录必须关联生成该建议时的用户当前投资情况快照
- **版本化审计：** 当建议因新信息或矛盾信息发生更新时，系统必须保留更新前后的版本记录
- **审计查询能力：** 审计记录必须支持按标的、时间区间、建议方向、置信度进行查询
- **删除审计留痕：** 建议记录删除后，系统仍应保留删除动作的时间、触发条件与删除范围日志
- **结构化输入留痕：** 建议生成所依赖的结构化信息摘要必须纳入审计范围，以支持事后复盘

### 边界控制

- **输出边界：** Web 界面与 README 必须持续展示“仅供参考，不构成投资建议”声明

### 滥用与误导风险控制

- **低置信度降级：** 系统可输出低置信度建议，但必须明确标记“低置信度”状态
- **矛盾信息标记：** 当信息间存在明显矛盾时，系统仍可生成建议，但必须展示矛盾来源与冲突信息
- **证据不足阻断：** 当建议缺少必要来源证据时，不得输出为正式建议

### 技术约束

- **数据获取：** 系统仅处理学习用途下可合法获取的公开信息
- **本地投资上下文：** 用户当前投资情况仅在本地存储，并仅用于生成建议时的参考输入
- **LLM幻觉防护：** 每条判断强制原文引用 + URL溯源链（已纳入技术成功指标）
- **数据时效性：** 简报元数据强制标注数据时间窗口，避免基于过时信息的建议

### 开源策略

- **License：** 采用限制性开源协议，限制商业使用
- **免责条款：** 对外文档与系统界面均需包含"不构成投资建议"声明

### 风险缓解

| 风险 | 缓解措施 |
|------|---------|
| LLM幻觉产生错误建议 | 强制原文引用 + URL溯源 |
| 信息源数据过时 | 简报标注时间窗口 + 采集失败可见 |
| 用户误信建议造成损失 | 免责声明 + 建议附带置信度 |

## Innovation & Novel Patterns

### Detected Innovation Areas

- **跨源事件关联分析：** 系统不只展示信息，而是把多个来源的相关内容归并为统一事件，帮助用户理解其关联影响
- **竞争性解释输出：** 系统在生成建议时应同时呈现支持与反驳信号，避免单一路径结论
- **信息源异常韧性：** 系统在信息源变化时应具备一定恢复能力，并在无法恢复时明确降级与上报
- **双层节奏输出：** 系统同时支持稳定的周期性输出与重要事件发生时的快速提醒
- **事件热度演变判断：** 系统可跟踪事件热度变化，为提醒优先级与关注顺序提供依据
- **多源弱信号合成：** 系统可在多个独立来源出现同方向信号时提升建议置信度

### Market Context & Competitive Landscape

- 现有工具（东方财富、雪球、Wind）侧重信息展示和社区讨论，不做自动化跨源关联分析
- 量化交易平台（聚宽、RiceQuant）侧重数值型因子和回测，不处理非结构化文本信息
- 本系统填补了"非结构化公开信息 → 结构化事件分析 → 可行动建议"这一链路的空白

### Validation Approach

- **事件关联准确性：** 事后回溯验证事件归并是否正确（误关联率追踪）
- **建议有效性：** 建议方向与实际股价变动的一致率持续追踪
- **异常恢复有效性：** 自动恢复成功率 vs 上报率
- **热度拐点预测准确性：** 热度变化判断与实际事件消退时间的偏差

### Risk Mitigation

| 创新风险 | 缓解策略 |
|---------|---------|
| 事件关联可能过度 / 误关联 | 增加事件级校验与去重 |
| 竞争性解释在金融场景中的有效性未验证 | 持续追踪建议准确性并迭代分析逻辑 |
| 自愈机制可能掩盖根本问题 | 所有自动恢复记录日志，定期 review |
| 热度判断参数需校准 | 初期使用保守参数，根据实际事件数据逐步校准 |
| 弱信号共振可能误触发 | 设置最低触发阈值与冷却窗口 |

## Web App Specific Requirements

### Project-Type Overview

本系统是一个以 Web 为主要交付面的信息分析与配置管理产品。Web 界面用于信息消费、配置管理和历史回溯；系统后端负责信息采集、分析处理与结果分发。

### Technical Architecture Considerations

**前端：**
- **架构：** SPA（Single Page Application）
- **浏览器支持：** 现代浏览器（Chrome/Firefox/Edge 最新两个主版本）
- **SEO：** 不需要
- **无障碍：** 至少保证核心查看与配置流程可通过键盘完成
- **实时更新：** Web 界面在新结果到达时应尽快刷新

**响应式设计：**
- Desktop 为主要使用场景
- Mobile 端主要依赖通知摘要，Web 界面移动端适配为低优先级

### Performance Targets

- Dashboard 首屏加载 <2s
- 信息列表/简报页面切换 <500ms
- 实时推送到 Dashboard 刷新延迟 <1s

### Implementation Considerations

- 系统应支持前后端职责分离
- 系统应支持事件驱动的 Web 界面结果刷新
- Web 界面状态应支持三级信息架构的渐进展开（摘要→简报→分析链）
- 通知应支持跳转到对应信息详情

## Project Scoping & Phased Development

### MVP Strategy & Philosophy

**MVP Approach：** Problem-Solving MVP — 验证核心价值链"采集→分析→推送"能否产出有用的交易建议
**开发资源：** 个人开发 + 自动化辅助工具支持
**目标周期：** 1 周

### MVP Feature Set (Phase 1)

**Core User Journeys Supported：** J1（日常简报）、J3（号外事件）

**Must-Have Capabilities：**
- 数据采集层：至少覆盖 3 类信息源（财经 RSS、交易所公告、社交舆情），并同时支持标准源直接接入与非标准源配置接入
- 信息分析：系统可对采集内容生成摘要、关键词与利好/利空分类
- 交易建议：系统可基于当期采集结果与用户当前投资情况输出买/卖/持有建议与核心原因
- 推送通知：系统可按优先级分级推送，并保证摘要在通知场景中可供快速判断
- 周期调度：系统可按固定频率运行常规采集与简报生成
- 事件去重：系统可基于唯一标识避免重复处理
- 配置管理：系统支持持仓/关注列表配置（配置文件级别，无 UI）
- 简报元数据：标注配置信息源/采集成功源/失败源/数据时间窗口

**MVP 不包含：**
- Web Dashboard（P2）
- 深度跨源验证与事件态势分析（P2）
- 深度多假设建议分析（P2）
- 实时源监听（P2）
- 自动恢复机制（P2）

### Post-MVP Features

**Phase 2 (Growth)：**
- Web 界面：三级信息架构（摘要→简报→分析链）+ 推送深链跳转
- 跨源验证：关键词事件归并、信源加权、矛盾检测
- 建议增强：多假设分析 + 多源弱信号共振触发
- 事件态势：生命周期状态机 + 热度量化 + 热度拐点判断
- 实时信息监听
- 全部 7 类信息源接入
- 标的/信息源配置界面
- 信息源异常自动恢复 + 上报机制
- 历史建议 vs 股价对比视图
- 分析参数调优入口

**Phase 3 (Expansion)：**
- 随机巡游式热点捕捉
- 号外冷却机制 + 号外回流简报
- 概率化归因输出
- 推送渠道模块化扩展
- 开源发布 + 社区化运营

### Risk Mitigation Strategy

| 风险类型 | 具体风险 | 缓解策略 |
|---------|---------|---------|
| 技术风险 | 非标准信息源接入成本不可预测 | MVP 优先接入标准源与结构化数据，复杂源逐步接入 |
| 技术风险 | 分析质量不稳定 | 强制原文引用 + 溯源链，持续迭代分析逻辑 |
| 市场风险 | 建议对交易决策的实际帮助程度未知 | MVP 快速验证，根据实际使用持续调整 |
| 资源风险 | 个人开发精力有限 | 自动化辅助工具支持；MVP 极简 |

## Functional Requirements

### 信息采集

- FR1: 系统可通过 RSS 订阅自动拉取财经新闻流 [P1]

## Non-Functional Requirements

### Performance

- **号外推送延迟：** 从信息源更新到用户收到高优先级通知 ≤1min（目标），≤5min（底线）
- **常规采集周期：** 30min 内完成全部信息源采集 + 分析 + 推送
- **分析处理延迟：** 单条信息的分析结果应在进入处理队列后 30s 内完成生成

### Security

- **凭据管理：** 所有外部服务凭据必须通过版本控制之外的安全方式管理，且不得硬编码进仓库
- **访问暴露：** Web 界面仅对授权用户可访问
- **数据边界：** 系统不得采集、存储或展示超出公开信息范围的敏感数据

### Reliability

- **自动恢复：** 单次进程级异常后，系统应在 5min 内恢复到可继续执行常规周期的状态
- **系统存活性：** 系统在正常运行期间，每30min至少产生一次可被用户感知的状态输出
- **采集降级：** 单个信息源采集失败不阻塞整体流程，且简报元数据必须标注失败源

### Integration

- **模型服务兼容性：** 系统应支持接入兼容 OpenAI 风格接口的模型服务
- **通知通道集成：** 系统应支持至少一种可用通知通道用于结果分发
- **信息源集成：** 系统应同时支持标准协议型信息源和自定义规则型信息源
- **数据持久化：** 系统应使用持久化存储保存事件、简报、建议与配置数据
